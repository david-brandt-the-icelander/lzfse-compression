# Benchmark: lzfse-zazzcat vs Apple's libcompression on an M1 Pro

- **Date:** 2026-11-13
- **Commit:** `1cdda37`
- **Machine:** the owner's MacBook Pro, Apple M1 Pro (10 threads), macOS 27.0.1, on AC power with Low Power Mode off. An earlier run on battery is kept at the end for comparison.
- **Command:**
  ```bash
  RUSTFLAGS="-C target-cpu=apple-m1" cargo run --release -p lzfse-bench -- --runs 11 --synthetic <session log>
  ```
- **Inputs:** the harness's synthetic corpus, plus the owner's largest Claude Code session log (a real file, labelled "session log" below).

## Method notes

- **Two runs agree:** the contenders are timed back to back on every run, so both face the same conditions. The battery run and the AC run gave the same speed ratios within a few percent. Absolute numbers were about 5–10% lower on AC for both libraries alike, probably from temperature or background load.
- **Correctness gate:** every chunk was decoded by both decoders before its timing counted.

## Summary

Each cell is our speed divided by Apple's, from the AC run. Above 1 means faster.

| Input | Encode | Decode | Parallel encode (10 threads) | Parallel decode (10 threads) |
|---|---:|---:|---:|---:|
| Session log (real) | 1.09–1.39 | 0.99–1.01 | 7.4–9.9 | 5.8–5.9 |
| Text | 0.97–1.00 | 0.75–0.76 | 6.0–7.6 | 3.9–4.1 |
| JSON + base64 | 1.8–2.2 | 1.09–1.11 | 6.9–10.9 | 6.1–6.6 |
| Binary | 0.87–1.03 | 0.83–0.87 | 4.9–6.5 | 3.9–4.5 |
| Noise | 2.2–2.3 | 41–52 | 4.6–9.2 | 26–33 |
| Zeros | 28–52 | 1.1–2.3 | 105–131 | 1.0–4.3 |

- **Ratio:** within 0.4% of Apple's on the real session log at 64 KiB chunks (0.480 vs 0.478), identical on the whole file, and within 0.3% on the synthetic inputs.
- **Real-world data:** on the workload `free-disk-space` targets, a Claude Code session log compressed in 64 KiB chunks as APFS stores it:
  - single-threaded, encoding is 9% faster and decoding is on par;
  - in parallel, encoding is 7.4× faster and decoding 5.8× faster.
- **Where we lose:** single-threaded decoding of plain text (about 25% slower) and binaries (13–17% slower), and single-threaded encoding of binary in 64 KiB chunks (13% slower). That is the remaining M4 work.
